# ควบคุมการสะท้อนหน้าจอจากแอปอื่น


ScreenOnAuto รับ intent สามแบบสำหรับเริ่ม หยุด หรือสลับการสะท้อนหน้าจอ อะไรก็ตามที่ส่ง intent ได้ — แอปทำงานอัตโนมัติ ทางลัดบนหน้าจอหลัก สคริปต์ผ่าน ADB หรือแอปที่คุณเขียนเอง — ก็ควบคุมการสะท้อนหน้าจอได้ การสะท้อนหน้าจอจึงเริ่มพร้อมกับการตั้งค่าอื่นๆ สำหรับการขับรถได้ โดยไม่ต้องกดเอง

## การทำงานสามแบบ

| Action | ทำอะไร |
|---|---|
| `idv.lzn.screenonauto.action.START_MIRROR` | เริ่มสะท้อนหน้าจอ ไม่ทำอะไรหากกำลังทำงานอยู่แล้ว |
| `idv.lzn.screenonauto.action.STOP_MIRROR` | หยุดสะท้อนหน้าจอ ไม่ทำอะไรหากไม่ได้ทำงานอยู่ |
| `idv.lzn.screenonauto.action.TOGGLE_MIRROR` | หยุดหากกำลังทำงาน เริ่มหากไม่ได้ทำงาน |

การส่ง action ซ้ำนั้นปลอดภัยเสมอ คำสั่งเริ่มที่ส่งมาขณะการสะท้อนหน้าจอกำลังทำงานอยู่จะถูกเพิกเฉย แทนที่จะปิดเซสชันแล้วสร้างใหม่ ดังนั้นสิ่งที่ทำงานทุกครั้งที่เชื่อมต่อบลูทูธจะไม่ขัดจังหวะการสะท้อนหน้าจอที่ทำงานอยู่แล้ว

## ในแอปทำงานอัตโนมัติ

แอปทำงานอัตโนมัติส่วนใหญ่มีส่วนประกอบเดียวกันภายใต้ชื่อเรียกของตัวเอง — โดยทั่วไปคือ action “ส่ง intent” ที่มีช่องประมาณนี้:

| ช่อง | ค่า |
|---|---|
| Action | หนึ่งในสาม action ด้านบน |
| Package | `idv.lzn.screenonauto` |
| Class | `idv.lzn.screenonauto.MirrorControlActivity` (หรือ `…MirrorControlReceiver` สำหรับ broadcast) |
| Target | Activity (หรือ Broadcast) |

ให้ใช้ Activity เว้นแต่จะมีเหตุผลที่ไม่ใช้ — สองหัวข้อถัดไปอธิบายความแตกต่าง และเหตุผลที่ไม่ควรพึ่ง broadcast ในการ*เริ่ม*สะท้อนหน้าจอ ไม่ว่าแบบใด ช่อง **Class** ก็ต้องกรอก หากเว้นว่างไว้ broadcast จะไม่ไปถึงเลย

หากมีอะไรไม่ทำงาน ให้ลองคำสั่ง ADB ที่ตรงกันด้านล่างก่อน ซึ่งจะบอกได้ว่าปัญหาอยู่ที่ intent หรือที่แอปที่ส่ง

## เริ่ม activity (แนะนำ)

ส่ง action ไปยัง `idv.lzn.screenonauto/.MirrorControlActivity` ในรูปแบบ **activity**:

```
adb shell am start -a idv.lzn.screenonauto.action.START_MIRROR \
  -n idv.lzn.screenonauto/.MirrorControlActivity
```

จะไม่มีอะไรของ ScreenOnAuto ปรากฏบนหน้าจอ และไม่เหลืออะไรไว้ในแอปล่าสุด คุณยังส่งคำสั่งเริ่ม*ก่อน*ถึงรถได้ด้วย — การสะท้อนหน้าจอจะรอ และเริ่มต่อเองเมื่อหน้าจอรถพร้อม

> **ℹ️ หมายเหตุ**
> Android ยังคงขอสิทธิ์บันทึกหน้าจอเมื่อเริ่มสะท้อนหน้าจอ หากต้องการให้ไม่ต้องแตะอะไรเลยจริงๆ ให้มอบสิทธิ์ล่วงหน้าหนึ่งครั้งผ่าน ADB — ดู[ให้สิทธิ์สะท้อนหน้าจอผ่าน ADB](/docs/th/grant-mirror-permission-via-adb/)

## ส่ง broadcast

action ทั้งสามแบบยังใช้เป็น **broadcast** ได้ โดยส่งไปยัง `idv.lzn.screenonauto/.MirrorControlReceiver` แทน:

```
adb shell am broadcast -a idv.lzn.screenonauto.action.STOP_MIRROR \
  -n idv.lzn.screenonauto/.MirrorControlReceiver
```

คำสั่ง**หยุด**ที่ส่งด้วยวิธีนี้จะเงียบสนิท — ไม่มีหน้าต่าง ไม่มีการกะพริบ

ต้องระบุคอมโพเนนต์เสมอ Android รุ่นใหม่จะไม่ส่ง broadcast ไปยังแอป เว้นแต่ผู้ส่งจะระบุว่าส่งถึงคอมโพเนนต์ใด broadcast ที่มีแค่ action จึงถูกทิ้ง และไม่มีอะไรเกิดขึ้นเลย โดยไม่มีข้อผิดพลาดใดๆ

> **⚠️ คำเตือน**
> คำสั่ง**เริ่ม**ที่ส่งเป็น broadcast ไม่น่าเชื่อถือ และเมื่อล้มเหลวก็จะล้มเหลวอย่างเงียบๆ ต้องอนุญาตสองอย่างก่อน ซึ่งโทรศัพท์หลายรุ่นปิดไว้โดยค่าเริ่มต้น:
>
> - **การเริ่มอัตโนมัติ** โทรศัพท์หลายรุ่นมาพร้อมการจัดการพลังงานที่ไม่ให้แอปถูกปลุกด้วย broadcast เลย มองหาตัวจัดการการเริ่มอัตโนมัติในการตั้งค่าแบตเตอรี่หรือตัวจัดการโทรศัพท์ แล้วอนุญาต ScreenOnAuto ที่นั่น โทรศัพท์อาจเตือนไม่ให้ทำ
> - **แสดงทับแอปอื่น** ให้สิทธิ์นี้แก่ ScreenOnAuto ในการตั้งค่าแอปของ Android
>
> หากต้องการแค่การเริ่ม ให้ใช้ activity ด้านบน — ไม่ต้องใช้ทั้งสองอย่างนี้

## การแก้ปัญหา

- **ไม่มีอะไรเกิดขึ้นเลย** — ตรวจสอบว่าระบุคอมโพเนนต์แล้ว broadcast ที่ไม่ระบุจะถูกทิ้งก่อนถึง ScreenOnAuto
- **หยุดได้แต่เริ่มไม่ได้** — คุณกำลังส่ง broadcast และขาดสิทธิ์หนึ่งในสองอย่างในคำเตือนด้านบน ให้ส่งไปยัง activity แทน
- **กล่องโต้ตอบขอสิทธิ์ปรากฏทุกครั้ง** — เป็นเรื่องปกติ เว้นแต่คุณจะให้สิทธิ์ล่วงหน้าด้วย [ADB](/docs/th/grant-mirror-permission-via-adb/)
- **คำสั่งเริ่มไม่ทำอะไรขณะการสะท้อนหน้าจอทำงานอยู่แล้ว** — เป็นเรื่องปกติเช่นกัน ดูด้านบน
